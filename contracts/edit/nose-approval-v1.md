# 생성 모델 코 편집 승인 v1

2026-10-27. 관련 Jira: S15P31B204-308·307·72·123. 1차 코 편집 지원은 리그 파일 존재만으로 열지 않는다.

3D-308 작업자는 원본 GLB·`rig.json`의 SHA-256, 원본 fit SHA, 엔진·리그·위상 버전, 모델별로 검증한 코 상대 범위를 만든다. 1차 등록 가능 코드는 `nose.bridge_height`, `nose.tip_projection`, `nose.tip_height`, `nose.tip_rotation`, `nose.alar_width`다. 코 외 코드는 등록하지 않는다. 범위의 각 끝값과 중립 상태를 같은 원본 GLB에서 최종 메시 검사하고, 단일 효과 내부 표본·대표 복합 조합·비대상 부위 이동의 3D-308 근거를 별도로 남긴다. 안전하지 않은 조합은 매 편집 시 INT-AI-02가 거절하거나 실제값으로 줄인다.

내부 시크릿이 있는 작업자는 모델 등록 뒤 `POST /internal/v1/face-models/{modelId}/nose-approval`을 호출한다. 본문은 아래 형태다. 서명 URL과 얼굴 파일은 본문에 넣지 않는다.

```json
{
  "schemaVersion": "v2",
  "binding": {
    "meshSha256": "<원본 GLB SHA-256>", "rigSha256": "<rig.json SHA-256>",
    "fitSha": "<원본 fit SHA>", "engine": "<코 엔진 버전>",
    "rigVersion": "<리그 버전>", "topologyVersion": "<위상 버전>"
  },
  "ranges": {
    "nose.bridge_height": {"min": -0.2, "max": 0.2}
  }
}
```

Spring은 DB에 저장된 모델의 S3 key에서 URL을 직접 발급해 중립과 각 범위 끝값을 사설 검사기에 보낸다. 응답의 해시·버전·실제값이 모두 정확히 일치할 때만 `approved_nose_capabilities`를 저장하고 `chat_apply_ready=true`로 연다. 실패하면 둘 다 바꾸지 않는다. 이 검사는 범위 내부 모든 조합의 안전을 보증하지 않으므로 채팅·슬라이더·점 저장은 요청마다 같은 검사기를 다시 호출한다. 기존 모델은 V11의 null/false 상태로 남으며 자동 승인되지 않는다.

신규 생성 모델은 결과 보고 전에 중립 상태를 확인하고, 코 코드별 감소·증가 방향을 상대 가중치 0.1, 0.25, 0.5, 0.75, 1 순서로 검사한다. 형상 또는 눈·입술 보호 검사에 실패하면 마지막 합격값(첫 표본 실패 시 중립)과 첫 실패값 사이의 중간값을 최대 세 번 검사하고, 실제 합격한 끝값만 승인한다. 미지원 방향, 보호 영역 정보 누락, 변형 없음은 이 탐색을 중단한다. 한쪽만 통과한 범위는 반대 끝값이 0이고, 양쪽 모두 통과하지 못한 코드는 생략한다. 통과한 범위와 원본·리그 결속은 INT-REC-03 성공 본문의 `noseApproval`에 넣는다. Spring은 코드별 후보 범위와 공통 카탈로그 범위가 겹치는 구간을 구하고, 중립만 남는 코드는 생략한다. 중립과 남은 구간의 끝값을 재검증하고, 통과한 범위를 저장한다. 승인할 코드가 없으면 [생성 결과 계약](../reconstruction/README.md)에 따라 코 편집을 잠근 채 모델을 등록한다. 화면의 감소·증가 끝은 해당 방향의 승인 끝값에 대응한다. 복합 조합은 편집 시 최종 피부를 검사한다. 직접 조절은 안전한 마지막 미리보기를 유지하고 서버는 검사를 통과한 저장값만 반영한다. 기존 모델은 원본·리그를 별도 검토한 뒤 같은 승인 API로 재승인해야 한다.

v1의 코 다섯 코드는 공통 카탈로그에서 상대 가중치 −1~1을 사용한다. 화면과 상담에는 모델별로 승인한 범위를 적용한다. 이미 승인된 모델에서 범위를 넓히려면 원본과 리그로 후보를 다시 계산한 뒤 재승인한다.

`GEOMETRY_LIMITS`는 변형 엔진의 탐색 상한이다. `pctD`는 모델의 코 높이를 기준으로 한 거리 비율이고, 실측 스케일이 확인된 모델은 mm를 쓴다. 각도는 도 단위를 쓴다. 코끝 돌출과 각도에 관한 [100건 후향 연구](https://pubmed.ncbi.nlm.nih.gov/25811564/)와 [3D 시뮬레이션의 수술 결과 비교 연구](https://pubmed.ncbi.nlm.nih.gov/31985623/)는 환자·수술별 차이를 보고한다. 이 결과로 엔진의 ±15 pctD나 ±20°를 임상 범위로 보정할 수 없으므로 탐색 상한을 유지한다. 편집 승인값은 각 모델의 형상 검사로 정한다.

문제가 발견되면 같은 내부 인증으로 `DELETE /internal/v1/face-models/{modelId}/nose-approval`을 호출해 즉시 false/null로 되돌린다. 이미 저장한 시안은 삭제하지 않고 읽기·undo를 보존한다. 승인과 취소를 사용자 공개 API에서 제공하지 않는다.
