# 코 자유 제어점 편집 v1

2026-10-27. 관련 Jira: S15P31B204-123·307·72. 1차는 코만 편집한다. 이 계약은 슬라이더 효과 코드와 별도의 자유 변위이며, 모델 회전 드래그와 구분한다.

`morphState.pointStrokes`는 선택적 배열이다. 각 항목은 원본 GLB의 피부 메시 `_TEMPLATE_INDEX` 정점 하나를 앵커로 삼는 `{ "vertex": 123, "delta": [0, 0.01, 0] }`이다. `delta`는 피부 메시 경계 상자 대각선에 대한 XYZ 상대 변위이며 소수 넷째 자리까지 저장한다. 최대 24개, 한 번의 이동은 길이 0.01 이하, 한 피부 점의 누적 변위는 0.15 이하로 제한한다. 반경은 대각선의 0.12로 고정하고 가장자리에서 0이 되는 완만한 감쇠를 쓴다. 리그의 코 영향 가중치가 0.2 이상인 앵커만 선택할 수 있고 코 영향이 0인 정점은 이동시키지 않는다. 같은 `_TEMPLATE_INDEX`를 공유하는 UV 경계 정점은 동일하게 움직인다.

화면은 움직이는 동안 After만 미리 바꾸고 손을 놓을 때 `PATCH /simulations/{id}/point-strokes`에 현재 `stateVersion`과 **전체 후보 배열**을 보낸다. Spring은 소유권·버전·승인된 모델/리그 해시를 확인하고 INT-AI-02에 현재 코 가중치와 현재/후보 점 배열을 함께 보낸다. 검사기는 같은 원본 GLB의 코 효과와 점 변위를 합친 최종 피부 메시에서 접힘·붕괴·새 자기교차를 검사한다. 검사 실패는 `EDIT_032`(409), 승인/검사기 준비 부족은 `EDIT_031`(409)이며 둘 다 저장하지 않고 미리보기를 버린 뒤 EDIT-03을 다시 읽는다. 성공하면 서버가 재검증한 배열만 시안 상태와 `morph_change.state_after`에 한 거래로 기록한다. undo/redo와 새로고침은 이 전체 상태를 복원한다. 채팅·슬라이더 편집 시에도 기존 점 배열을 포함해 최종 메시를 검사한다.

앵커 인덱스와 변위는 현재 모델·리그 결속에서만 유효하다. 모델 파일이나 리그가 바뀌면 기존 배열을 다른 모델에 적용하지 않는다. 눈·입술·턱을 지정한 점 이동은 허용하지 않는다. 원본 GLB와 리그가 없거나 승인 정보가 없으면 UI의 점 핸들을 표시하지 않는다.

## 코 구조 손잡이 (S15P31B204-432)

새로 조작하는 코 손잡이는 자유 점 변위를 추가하지 않는다. 콧대 손잡이는 `nose.bridge_height`, 코끝 손잡이는 `nose.tip_projection`과 내림 쌍(`nose.tip_height = -0.6v`, `nose.tip_rotation = -0.4v`), 양쪽 콧볼 손잡이는 공통 `nose.alar_width`를 조절한다. 화면의 ±100%는 각 모델에 승인된 범위의 끝값이다. 정면에서 보이지 않는 깊이 이동과 측면에서 보이지 않는 콧볼 너비 이동은 제공하지 않는다. 드래그 중에는 After만 미리 바꾸고 놓을 때 기존 `PATCH /simulations/{id}/morph-state`로 변화한 효과를 한 요청에 저장한다. 서버의 승인 범위·최종 메시 검사·버전 확인·undo가 슬라이더와 동일하게 적용된다.

기존 `morphState.pointStrokes`는 계속 읽어 같은 메시를 재현하고 이력/undo로 복원한다. 새 UI는 점 배열을 추가하지 않으므로 과거 24개 제한을 새 손잡이에 적용하지 않는다. 위 v1 자유 점 API 계약은 기존 데이터와 호출의 호환성 문서로 유지한다.
