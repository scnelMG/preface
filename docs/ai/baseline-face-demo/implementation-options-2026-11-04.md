# 3D 얼굴 분석 → 근거형 첫 수정 제안: 구현 선택지와 실행 계획

2026-11-04 · AI-579 기술 계획. 기획 원본 `docs/planning/`을 변경하거나 제품 출시를 승인하지 않는다.

## 사용자가 실제로 받는 결과

3D 생성 후 **현재 얼굴의 정면 윤곽·코의 정면/옆모습을 쉬운 말로 설명**하고, 근거가 있는 경우 **먼저 비교할 한 위치·방향·이유**를 보여 준다. 원본과 작은 변형을 같은 카메라에서 비교한다. 사용자가 선택하기 전에는 편집·저장이 발생하지 않는다. 근거가 방향까지 뒷받침하지 않으면 관찰과 양방향 탐색 또는 보류만 보여 준다. 시술명·결과 예측·미모 점수는 만들지 않는다.

예시(가정한 조건이 모두 통과한 경우): “정면에서 콧볼 바깥 폭이 두 눈 안쪽 사이보다 조금 넓게 측정됐어요. 코를 살필 때 이 두 위치를 함께 보는 전문가 관찰법이 있습니다. 콧볼 폭을 작게 줄인 모습부터 원본과 비교해 보세요.” 정확한 점과 차이의 오차 범위가 확인되지 않으면 이 문장은 나오지 않는다. 문헌의 ‘검토할 수 있음’을 이 얼굴에 맞는 수술이나 정답으로 바꾸지 않는다.

현재 Spring 상담은 `measurements:{}`를 GMS에 보내고, 모델 상세 API는 측정값을 내리지 않는다. 분석 경로는 기존 채팅 편집과 분리한다. **검증된 텍스트 수치의 GMS 전송도 AI-122의 허용 필드·처리 조건이 확정되기 전에는 열지 않는다.** 실제 사진·영상·3D 렌더·GLB의 GMS 전송은 REQ-N-10에 따라 금지한다.

## “전문가 지식”을 답변에 반영하는 방법

1. 출처를 `측정 정의 / 관찰 순서 / 조건부 비교 / 한계 / 집단 통계`로 분리하고, 각 카드에 적용 대상·조건·금지 추론을 적는다. [10-7-5 코 분석](https://pmc.ncbi.nlm.nih.gov/articles/PMC7159929/)은 정면·옆·아래 시점의 관찰 순서에, [콧볼 폭 전문가 서술](https://pmc.ncbi.nlm.nih.gov/articles/PMC9337225/)은 엄격한 조건부 비교 가설에만 쓴다.
2. 현재 카드 9개는 벡터 DB 없이 `측정 ID → 허용 카드`로 조회한다. 자료가 많아질 때만 BM25·벡터 혼합 검색과 재정렬을 시험한다. 검색 품질이 낮으면 보류한다([CRAG](https://arxiv.org/abs/2401.15884)).
3. GMS는 검증된 ID와 수치로 **짧은 한국어 설명 초안**을 쓰거나 합성 자료의 시각 불일치를 탐색한다. 출력은 관찰 ID·근거 ID·조절 ID·보류 사유의 닫힌 스키마다. 서버가 문장별 출처·대상·조건을 재검사한다. 실제 출처라도 다른 대상의 근거를 잘못 붙일 수 있다([Deceptive Grounding](https://arxiv.org/abs/2607.09349/)).
4. 방향은 LLM 자유 선택이 아니라 **근거의 허용 범위 ∩ 검증된 3D 관찰 ∩ 사용자 목표(있다면) ∩ 모델 지원·안전성**으로 정한다. 여러 후보가 통과하면 강한 근거, 낮은 측정 불확실성, 보이는 변화 순서로 하나를 선택한다. 사용자 목표가 없을 때도 조건부 첫 비교는 가능하지만 ‘가장 어울림’으로 단정하지 않는다.

**작업량 추정(한 명씩 AI·BE·FE가 맡고 기존 편집 엔진을 재사용한다는 가정):** 첫 2일은 이미 생성된 사용 허가 모델 5개에서 점 후보를 표시하는 탐색이다. 위치가 안정적이면 3D·AI 측정/품질 3~5일, 근거 게이트 1~2일, BE 계약·권한·캐시 2~3일, FE 카드·비교 2~3일, 공동 QA 2~4일이다. 병렬 작업을 감안한 A안의 **첫 출시 후보는 약 2~3주**로 추정한다. 확보 모델과 담당 인력이 확인되지 않았으므로 약속된 일정이 아니다. 5개 탐색에서 콧볼 최외곽 또는 광대·턱 후보가 불안정하면 자동 점 ID 매핑을 고치거나 해당 관찰을 제외하는 방향으로 범위를 다시 정한다. B안의 실제 얼굴 멀티모달과 C안의 유사 집단 통계는 기획·데이터 선행 조건이 없어 현재 일정에 넣지 않는다.

검증 규모는 회의에서 확정할 제안이다: 서로 다른 생성 모델 **최소 20개**에서 정면·45°·측면 점과 전후 형상을 확인하고, 초보 사용자 **10명 정도**에게 설명·근거·비교가 첫 선택에 도움이 되는지 관찰한다. 이 숫자는 임상적 표본 크기나 현재 확보량이 아니다. 고정 수치 오차 임계값을 임의로 정하지 않는다. 두 표시자의 차이와 모델별 측정 변동으로 오차 구간을 먼저 만들고, 관찰 차이가 그 구간을 넘는지 확인한다. 자동 3D 특징점의 임상 정확도를 가정하지 않는다([체계적 검토](https://pubmed.ncbi.nlm.nih.gov/37042196/)).

**출시 차단:** 실제 얼굴의 근거 없는 방향 문장, 지원 밖 조절, 원본 변경, 자기교차·비공/코 밖 변형, 타인 모델 노출이 한 번이라도 확인되면 수정 전까지 막는다. “전문의가 이 얼굴을 진단했다”는 표현도 쓰지 않는다. 한 영역의 품질만 불확실하면 그 영역의 분석·제안만 숨기고 기존 편집은 유지한다.

## 현재 결론

**A안을 먼저 만든다.** 실제 얼굴에 대해 “지금 보이는 특징 → 먼저 비교할 변화 → 근거 → 원본과 전후”는 기존 스택으로 구현 가능하다. 다만 현재 PoC의 점·측정 계약으로는 개인별 방향을 아직 열 수 없다. B안은 합성 평가와 문장 생성 보조에 한정하고, C안은 실제 동의 데이터가 마련될 때까지 보류한다. 이 계획을 ‘전문가가 개인에게 시술을 추천하는 기능’이라고 부르지 않는다.

## 팀이 바로 실행할 A안 작업 명세

### A1. 점·측정 검증 (AI-122·578, 3D/AI)

기존 사용자에게 허가받은 **이미 생성된** 모델 5개를 먼저 고른다. 원본 영상 재촬영은 요구하지 않는다. 모델별 `meshSha256`·리그/위상 버전과 정면·45°·측면 이미지를 원래 보관 범위 안에서만 확인한다. 현재 [`glb_geometry_poc.py`](scripts/glb_geometry_poc.py)는 공개 합성 모델에서 점 후보를 색으로 표시하는 탐색 도구다. 실제 모델용 도구를 만들 때는 해시·소유 권한·출력 위치를 별도로 제한하고 실제 얼굴 렌더를 Jira·MR·GMS에 넣지 않는다.

1. 점 정의표를 고정한다: 눈 안쪽 모서리(`endocanthion`), 콧볼 *가장 바깥 경계*(`alare`), 광대 바깥(`zygion`), 턱각(`gonion`), 코끝(`pronasale`). 템플릿 ID는 **후보**일 뿐이다. 현재 `evaluate.py`의 `alar_crease`는 오목한 주름 위치라 `alare`로 이름만 바꾸면 안 된다. [3D 얼굴 측정 정의](https://pmc.ncbi.nlm.nih.gov/articles/PMC13466362/)와 [MediaPipe 점 맵](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/face_mesh.md)을 분리해 읽는다.
2. 두 팀원이 각 모델의 세 시점에 점을 독립 표시한다. 일치하지 않는 점은 사진 프레임·메시의 가림/텍스처 문제를 기록하고, 불확실하면 `unverified`다. 팀원은 **형상 위치**를 확인하며 의료적 적합성을 판정하지 않는다.
3. 먼저 정면 투영 폭 비율 `r_alar = |x(al_L)-x(al_R)| / |x(en_L)-x(en_R)|`, `r_jaw = |x(go_L)-x(go_R)| / |x(zy_L)-x(zy_R)|`을 정의한다. `x`는 승인된 정면 기준 좌표의 가로축이다. 길이는 GLB 임의 단위이므로 비율만 표시한다. 코끝 앞뒤는 코 시작점·콧볼 기준면·턱끝이 함께 검증되기 전에는 수치화해도 방향 제안에 쓰지 않는다.
4. 점 표시자 차이, 재생성/반복 측정 차이와 3D 복원 품질을 기록해 **측정 오차 구간**을 정한다. 예컨대 콧볼/눈 폭의 두 구간이 겹치면 “더 넓다”도 말하지 않는다. 5개 탐색에서 외곽 점 매핑이 안정적이지 않으면 점 ID 고정 방식은 중단하고 메시 윤곽에서 최외곽을 찾는 방식 또는 해당 지표 제외를 비교한다.

산출물은 **점 정의표, 모델별 품질·오차 집계, 가능한 지표 목록**이다. 얼굴 원본이나 개별 점 좌표는 이슈 댓글·MR에 넣지 않는다. 자동 3D 특징점은 별도 대조 없이는 임상 정확도를 주장할 수 없다. [자동 점 추출 체계적 검토](https://pubmed.ncbi.nlm.nih.gov/37042196/)

### A2. 기존 결과 계약에 분석값 연결 (AI-122·578, 3D/BE)

워커 성공 보고의 [`measurements`](../../../contracts/reconstruction/schemas/result-request.schema.json)는 이미 선택 필드이고, Spring `face_model.measurements` 저장 칼럼도 있다. 현재 워커는 값을 보내지 않는다. 새 DB 테이블을 먼저 만들지 말고 **기존 필드 안에 버전 있는 허용 구조**를 넣는다. 예시 구조는 아래와 같다. 필드 이름·제약은 `contracts/` MR에서 FE·BE·AI가 함께 확정한다.

```json
{
  "schemaVersion": "v1",
  "sourceMeshSha256": "<원본 GLB SHA-256>",
  "rigVersion": "<승인 리그 버전>",
  "metrics": {
    "frontalAlarToIntercanthal": {
      "value": 1.08,
      "unit": "ratio",
      "quality": "verified",
      "interval": [1.04, 1.12],
      "landmarkDefinitionVersion": "v1"
    }
  }
}
```

예시 숫자는 **가상값**이다. 원본 해시·리그/위상 버전 불일치, NaN·무한대, 잘못된 단위·점 품질은 해당 지표를 버린다. 실제 얼굴 측정값의 GMS 전송은 별도 처리 조건이 확정될 때까지 계속 비운다. 현재 모델 상세 응답은 측정값을 내리지 않으므로 소유자 인증을 거친 **분석 전용 읽기 응답**을 만든다. 원본 GLB URL이나 개별 좌표 대신 허용된 관찰·품질·출처 ID만 내려준다. `contracts/` 변경은 팀원 승인 규칙을 따른다.

BE/FE 협의에 낼 **최소 API 초안**은 다음 두 개다. 현재 존재하는 API라고 간주하지 않는다.

- `GET /api/v1/face-models/{faceModelId}/analysis`: 소유권·원본 해시를 확인하고 `status`, `sourceMeshSha256`, `measurementVersion`, `evidenceVersion`, 근거·품질이 붙은 `observations`, `firstComparison`만 반환한다. 원본 GLB URL·점 좌표는 응답에서 뺀다.
- `POST /api/v1/simulations/{simulationId}/analysis-preview`: `stateVersion`, `controlId`, `direction`을 받아 **저장 없이** 기존 내부 검사기로 현재 시안의 후보를 확인하고 `candidateWeights`, `viewHints`, `status`를 반환한다.

선택 시에는 기존 `PATCH /simulations/{id}/morph-state`로 다시 검증·저장한다. 첫 API는 **원본 모델**, 둘째는 **현재 시안**을 기준으로 하며 서로 섞지 않는다. 기존 편집 API만으로 미리보기를 만들면 자동 저장되므로 이 분리가 필요하다.

### A3. 근거 판단과 후보 생성 (AI-579, AI/BE)

검수 카드에는 `적용 대상`, `필요 지표`, `조건`, `혼동 요인`, `허용 문장`, `금지 추론`, `출처 버전`을 둔다. 현재 9개 카드를 대상으로는 정확한 ID 조회가 전부다. YouTube·홍보 칼럼은 표현 참고가 될 수 있어도 방향 판단 근거 카드에는 넣지 않는다. `population_context_only`·`limitation` 카드는 개인의 조절 방향을 열 수 없다.

첫 규칙의 예: 두 외곽 점이 검증됐고 `r_alar`의 **오차 구간 전체가 1보다 큰** 모델에서만 전문가 서술을 ‘콧볼 좁힘의 작은 비교 가설’에 연결한다. 이것은 개인의 이상 비율이나 수술 권유가 아니다. [출처](https://pmc.ncbi.nlm.nih.gov/articles/PMC9337225/)가 서술적 의견이라 더 강한 표현은 금지한다. 광대/턱 비율은 얼굴형 관찰 문장에만 쓰며, “계란형으로 바꾸자” 같은 방향으로 연결하지 않는다. 목표가 없고 어느 방향 근거도 통과하지 않으면 **원본 설명 + 사용자가 고를 수 있는 양방향 비교**를 내되 자동 추천이라고 부르지 않는다.

코 네 사용자 조절의 **근거 확보 순서**는 다음과 같다. [전문가의 정면·측면·아래 시점 관찰법](https://pmc.ncbi.nlm.nih.gov/articles/PMC7159929/)은 관찰 항목을 제공하지만 네 방향의 개인별 정답을 모두 주지는 않는다. 카드 한 장마다 원문에 있는 조건을 짧게 재서술하고 다른 팀원이 출처와 허용 문장을 대조한다. 전문의의 개별 검수로 표시하지 않는다.

| 화면 조절 | 필요한 검증된 3D 관찰 | 지금 허용 가능한 설명 | 방향을 열기 전 추가 근거 |
| --- | --- | --- | --- |
| 콧볼 너비 | 정면 `alare` 양쪽·눈 안쪽 폭과 오차, 아래 시점 비공 경계 | 폭 관계를 설명. 조건부로 작은 **좁힘 비교 가설** | 최외곽 점 대응·실제 morph와 비공 안전. 문헌은 시술 결과·적정 조절량을 주지 않음 |
| 콧대 높이 | 측면 코 시작점·콧대 윤곽, 이마/코끝 맥락 | 상대적인 시작 위치와 옆모습 관찰 | 현재 “높여야 함”의 개인별 근거 없음. 사용자가 목표를 말하거나 별도 검수 근거가 생길 때까지 양방향 탐색 |
| 코끝 앞뒤 | 코끝·콧볼 기준면·코 시작점·턱끝 | 코끝 위치를 턱·코 시작점과 함께 설명([기본 원칙](https://pmc.ncbi.nlm.nih.gov/articles/PMC3109328/)) | 턱끝/기준면 오차와 실제 morph 효과 검증. 단일 비율로 앞/뒤 정답 결정 금지 |
| 코끝 위아래 | 코끝·코밑·윗입술·옆/아래 시점, UI의 두 morph 결합 | 코끝 방향과 입술 관계 관찰 | 회전·높이 두 저장값의 동시 효과와 비공 경계 검증. 개인별 올림/내림 목표는 아직 없음 |

공개 자료의 역할도 구분한다. [FaceBase](https://www.facebase.org/help/faqs/)의 공개 요약치는 측정 정의와 사람 간 변이를 이해하는 참고이며, 개별 3D 얼굴은 별도 접근 승인이 필요하다. [FaceScape 허가서](https://nju-3dv.github.io/projects/FaceScape/static/license/LicenseAgreement_FaceScape.pdf)는 학생 신청과 상업 이용을 제한하므로 제품의 학습·검증 데이터로 가져오지 않는다. 유튜브·홍보 칼럼은 설명 방식 참고에만 쓰고 개인 방향의 판정 규칙으로 사용하지 않는다.

GMS는 허용된 `metricId`·`evidenceId`·`controlId`·관찰 문장을 입력받아 쉬운 한국어 1~2문장만 작성한다. 서버는 문장별 출처와 지표 대상, 새 숫자·시술명 유무를 검사한다. 실패·타임아웃이면 검증된 고정 문장으로 대체한다. 카드 수가 작아 지금은 검색 인프라보다 이 방식이 신뢰 가능하다. 자료가 늘면 검색 품질 검사([CRAG](https://arxiv.org/abs/2401.15884))와 문장별 근거 귀속 검사([TripleCheck](https://aclanthology.org/2025.hcinlp-1.4/))를 **보류율·오답률 비교 실험 후** 도입한다.

후보는 실제 UI의 코 조절 4개 중 모델이 지원하는 것만 허용한다. `nose.tip_height`와 `nose.tip_rotation`이 함께 움직이는 화면의 ‘코끝 위아래’는 **하나의 사용자 조절**로 취급한다. 모델별 승인 범위의 작은 양을 몇 단계 시험하되, 화면 %를 실제 치수 %로 해석하지 않는다. 각 후보를 현재 사설 코 검사기에 보내 최종 메시의 비공 경계·자기교차·코 밖 변형을 확인한다. 현재 편집 API는 전부 즉시 저장하므로, **미저장 미리보기용 서버 검증 경로**가 필요하다. 검증 결과와 `stateVersion`을 받은 뒤 FE가 기존 뷰어에서 같은 시점의 Before/After를 렌더하고, 사용자가 ‘적용’을 누를 때만 기존 morph-state PATCH를 호출한다. 그때도 최신 상태에서 다시 검증한다.

### A4. 제품 화면과 끝단 검증 (FE/BE/QA)

카드는 `지금 보이는 특징 → 먼저 비교할 위치·이유 → 근거 보기 → 원본/작은 변화 → 적용 또는 건너뛰기` 순서다. 측정값의 숫자를 전면에 내세우지 않는다. 품질이 나쁜 지표만 숨기고 편집 가능한 다른 부위는 유지한다. 재진입한 같은 원본 해시·측정/근거 버전은 다시 계산하지 않는다.

합성 회귀에는 반전된 점, 가려진 점, `r_alar` 오차 구간의 1 교차, 다른 근거 ID, 미지원 코 코드, 뒤집힌 방향, 오래된 시안 버전, 검사기 503/타임아웃, 근거 없는 GMS 문장, 타인 모델 접근을 넣는다. **근거 없는 방향·지원 밖 조절·원본 변형·안전 검사 실패 후보 노출은 0건**이어야 한다. 실제 생성 모델 20개 제안은 형상·점 검수용이며 임상 적합성 표본이 아니다. 초보자 약 10명에게 첫 비교의 이유를 자기 말로 설명하게 하고, ‘의사가 시술을 권했다’고 오해한 사례를 별도 기록한다. 3D 완료→분석, 후보 검사→전후 표시의 p50/p95와 실패율을 **실제 운영과 같은 워커 자원**에서 잰 뒤 수용 목표를 확정한다.

평가는 세 세트로 분리한다. **개발 세트**는 합성 변형과 처음 5개 모델로 점·문구를 조정한다. **보류 세트**는 조정에 쓰지 않은 실제 생성 모델에서 점·방향·형상 실패를 검수한다. **초보 사용자 세트**는 제시 순서를 바꿔 현재 튜토리얼만 본 경우와 분석 카드를 본 경우의 첫 조작까지 걸린 시간·근거 이해·원본 복귀·부담감을 비교한다. 한 세트의 문장을 고쳐 그 세트만 재시험하는 방식은 피한다. 의료적 타당성·수술 만족도는 이 평가로 입증하지 않는다. 제품 게이트는 안전 실패 0건과 독립 보류 세트에서의 수치·근거 정합, 그리고 초보 사용자가 ‘비교 제안’과 ‘의료 권유’를 구분하는지에 둔다. 표본 크기와 UX 목표 수치는 첫 파일럿 후 확정한다.

GMS 합성 PoC에서는 Astra/Luna의 점 위치 판단이 서로 달랐다. 모델 이름이나 파라미터 수가 전문의 판단을 보증하지 않는다. 위 로컬 모델의 Apache-2.0 표시는 **코드·모델 사용 허가 확인의 출발점**이며, 얼굴 분석 적합성은 별도 평가해야 한다. [공식 모델 카드](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct) 실제 사용자 렌더를 외부 GMS로 보내려면 기획 원본과 동의·처리방침의 이 목적을 먼저 변경해야 한다. 기존 ‘AI 관상’의 별도 사진 전송 동의를 이 기능에 재사용하지 않는다.

**바로 실행할 B1 평가:** 현재 [합성 GLB 렌더·GMS 점검 도구](real-glb-grounding-poc.md)에서 정답 위치 20장과 한 점쌍을 귀/주름/반대편으로 의도적으로 옮긴 20장을 만든다(모두 공개 합성 모델). 어느 그림이 오류인지 숨긴 채 Astra·Luna에 동일한 닫힌 스키마로 판정시킨다. 점쌍별 `MISPLACED` 발견, 정상점 오경보, `UNCLEAR` 비율, 호출 p50/p95, 관측 잔액 차이를 기록한다. **오류 그림을 `PLAUSIBLE`로 확신하는 사례가 있으면** 모델 출력을 품질 게이트로 삼지 않는다. B2도 같은 보류 세트를 써서 비교하고 H200 공유 환경에서만 먼저 실행한다. 운영 워커가 공유하는 GPU에서는 모델을 띄우지 않는다. 운영 GPU의 24GB·동시 처리 여유는 별도 실측 전까지 미확인이다.

## C안: 유사 집단 경향의 실행 조건

AI-580의 [합성 검증](../similar-cohort-synthetic-feasibility.md)은 소수 집단·중복 계정·화면 버전·노출 순서에 따른 착시를 재현했고 실제 데이터 도입을 **보류**했다. 제품 논의가 시작되면 먼저 개인정보·기획 담당이 이 통계 목적의 별도 동의, 보관·철회·탈퇴 삭제, 최소 얼굴 특징 범주를 승인해야 한다. 그 뒤 `shown → try → undo`를 **표시 순서·화면/모델 버전과 함께** 기록하고, 고르게 배치된 노출을 분모로 집계한다. 개인 얼굴, 영상, 메시, 개별 랜드마크를 통계용으로 추가 수집하지 않는다.

게시 전에 작은 집단·겹치는 필터·반복 조회로 개인을 짐작할 수 있는지 확인하고, 실제 동의 표본에서 표본 부족·순서 효과를 평가한다. 표본 규모 기준은 개인정보 검토와 관측 분포를 보고 정하므로 지금 숫자를 임의로 고정하지 않는다. 문구는 “이 특징 범주의 이용자가 **시험해 본** 변화”까지만 허용한다. `try`는 선호·만족·시술 결과가 아니다. [ASPS 시술 총건수](https://www.plasticsurgery.org/documents/news/statistics/2024/plastic-surgery-statistics-report-2024.pdf)나 [지역 전문가 조사](https://pmc.ncbi.nlm.nih.gov/articles/PMC7605391/)로 빈 얼굴형별 통계 셀을 채우지 않는다. 운영 데이터 수집·화면 노출은 이 계획과 별도 결정이다.

## 착수 첫날 재현 명령과 체크 결과

저장소 루트에서 공개 합성 자료만 사용한다. 실제 사용자 얼굴이나 비밀값은 이 명령에 넣지 않는다.

```sh
python docs/ai/baseline-face-demo/scripts/glb_geometry_poc.py --model base-female --output artifacts/ai579-real-3d-poc/female
python docs/ai/baseline-face-demo/scripts/glb_geometry_poc.py --model base-male --output artifacts/ai579-real-3d-poc/male
python -m unittest discover -s docs/ai/baseline-face-demo/scripts -p 'test_*.py'
python scripts/eval/similar_cohort_synthetic.py
```

앞선 PoC에서는 22개 관련 검사가 통과했고 두 합성 GLB의 방향 판정이 `deferred`였다. 마지막 명령의 합성 유사 집단은 모든 작은 셀을 숨기고 실제 도입을 보류한다. 작업 시작 시 같은 결과가 재현되는지 확인한 뒤, **A1의 기존 생성 모델 점 검수**로 넘어간다. 두 모델의 `1.019`·`1.113`은 미검증 후보점 비율이며 사용자 추천 임계값이나 실제 얼굴 통계가 아니다.
