# 원본 얼굴 분석 → 첫 비교 시안: 근거·설계 검토 (AI-579)

2026-11-04 기준 **합성 검증 설계**다. 실제 사용자의 얼굴 분석이나 성형 추천을 출시 승인한 문서가 아니다. 제품 요구사항의 원본은 `docs/planning/`이며 이 문서는 그 내용을 바꾸지 않는다.

## 사용자에게 보여 줄 순서

1. 원본 3D의 정면·측면에서 **확인 가능한 특징**을 쉬운 말로 설명한다. 얼굴형 이름이나 미모 점수를 강제로 붙이지 않는다.
2. 첫 비교 지점 하나를 고른 이유와 근거의 한계를 함께 보여 준다. 사용자가 목표를 말하지 않아도 시작할 수 있지만, “전문가가 이 얼굴에 수술을 권했다”로 표현하지 않는다.
3. 원본과 작은 변경을 같은 각도·조명으로 나란히 보여 준다. 원본은 불변이며 사용자가 선택하기 전 저장하지 않는다.
4. 근거·측정·형상 검사가 부족하면 방향과 시안을 보류하고 확인 가능한 관찰만 보여 준다.

## 미리 넣은 근거

`evidence-cards.json`을 버전이 있는 허용 목록으로 읽는다. 전문 논문의 **짧은 재서술 주장**만 보관하고 전문·사진·도표는 복제하지 않는다. 카드마다 출처 유형, 허용 용도와 한계를 분리했다.

| 카드 | 허용하는 설명 | 막아야 할 비약 |
| --- | --- | --- |
| `FACE_SHAPE` | 광대와 아래 얼굴을 함께 관찰 | 특정 얼굴형이 더 아름답다 |
| `NOSE_LANDMARKS` | 눈 안쪽·콧볼 경계의 측정 위치 정의 | 자동 특징점이 정확하다 |
| `NOSE_VIEWS` | 정면·측면·아래쪽을 구분해 관찰 | 정면 한 장으로 전체 코를 판정 |
| `TIP_CHIN_CONTEXT` | 코끝과 턱끝·코 시작점의 상호 영향 | 턱 정보 없이 코끝 앞뒤 방향 추천 |
| `ALAR_FIRST_COMPARISON` | 콧볼 폭이 눈 안쪽 거리보다 넓은 **합성 사례**에서 좁힘을 비교 가설로 시험 | 개인별 정답, 실제 수술 효과, 조절량·안전 범위 |
| `AESTHETIC_LIMITS` | 이상 비율의 근거가 불충분하다는 한계 | 미모 점수·정답 비율 |
| `NOSE_PREFERENCE_VARIATION` | 코 선호가 문화·맥락에 따라 달라진다는 한계 | 보편적으로 가장 어울리는 코 단정 |
| `OBSERVED_REQUEST_TRENDS` | 소규모 전문가 조사의 관찰 맥락 | 유사 얼굴 사용자에게 흔한 시술이라는 개인화 주장 |
| `PROCEDURE_VOLUME` | 시술별 집계 규모의 맥락 | 특정 얼굴형의 시술 빈도·성과 추론 |

마지막에서 두 번째 카드는 [비수술 코 성형의 서술적 전문가 의견](https://pmc.ncbi.nlm.nih.gov/articles/PMC9337225/)이다. 논문에 있는 것은 `콧볼 폭 > 눈 안쪽 거리`일 때 소폭 좁힘을 검토할 수 있다는 의견이지, **115%라는 임계값이나 −15%라는 조절량이 아니다.** 앞선 합성 화면의 115%·−15%는 그림을 만들기 위한 임의 값이므로 근거 카드에 넣지 않았다. 인종·문화별 선호나 개인 취향도 반영하지 못한다. 이 카드 하나로 실제 사용자에게 방향을 단정하지 않는다.

## 데이터와 결정 경계

```text
원본 GLB/리그 + 원본 해시
  → 해부학적 특징점·측정 정의 버전·품질 (AI-122·578)
  → 해당 측정 ID에 허용된 근거 카드 선택
  → 쉬운 한국어 관찰 (값·근거 ID 검증)
  → 후보 방향 게이트 (AI-579)
  → 모델 capabilities ∩ 안전 범위 ∩ 실제 조절 UI ∩ 형상 검사
  → 같은 시점의 원본/후보 3D → 사용자 선택 → 기존 저장·재조회·undo
```

작은 허용 목록에는 벡터 검색보다 **측정 ID로 카드를 직접 선택**하는 편이 적합하다. GMS가 관찰 표현을 돕더라도 출처·수치·조절 방향·조절량을 새로 만들지 못한다. 전문가가 정답으로 표시한 얼굴별 자료가 없으므로 파인튜닝의 학습·평가 근거도 없다. 실제 사용자 경로에서 GMS에 전달할 수 있는 것은 현행 REQ-N-10에 맞는 검증된 텍스트 문맥뿐이다. 얼굴 사진·영상·3D 렌더·GLB는 전송하지 않는다. 합성 이미지 전송 시험은 제품 전송 허용의 증거가 아니다.

`scripts/comparison_policy.py`는 현재 **합성 입력 전용**이다. 카드 출처, 시각적 정합, 특징점 신뢰, 시점, 모델 지원, 안전 범위, 형상 검사를 확인하고 조건 하나라도 빠지면 방향을 보류한다. 조건을 모두 통과해도 출력은 `preview_hypothesis`이며 **조절량은 비워 두고 적용 상태는 false**다. 실제 모델에는 항상 보류한다. 제품의 작은 조절량은 기존 모델별 승인 범위와 검증기가 정해야 한다.

## 설계 검증 결과와 남은 게이트

| 검증 | 현재 결과 |
| --- | --- |
| 출처 없는 카드·다른 부위·주입 응답 | 합성 게이트에서 방향 보류 |
| 콧볼이 눈 안쪽 거리 이하, NaN·누락 측정 | 방향 보류 |
| 특징점·시점·지원 조절·안전 범위·형상 중 하나 실패 | 방향 보류 |
| 합성 사례에서 모든 게이트 통과 | 콧볼 너비를 좁혀 **비교할 가설**만 생성, 조절량·적용 없음 |
| 실제 사용자 모델 | 현재 무조건 방향 보류 |
| 기존 관찰형 GMS 시험 | 관찰 카드만 입력·출력 허용, 비교 방향 카드는 전송하지 않음 |

제품 연결 전에는 서로 다른 생성 모델에서 눈 안쪽과 콧볼 바깥 경계의 **실제 점 위치·오차**를 사람이 대조해야 한다. 경계가 부정확하면 `콧볼 폭 > 눈 안쪽 거리` 조건 자체가 무의미하다. 정면·45°·측면에서 후보 변화가 보이는지, 비공 경계·자기교차·코 밖 변형이 없는지 검사하고 저장·재조회·undo를 반복 확인해야 한다. 사용자에게 관찰과 비교 가설을 구분해 이해시키는지도 따로 평가해야 한다. 정량 목표는 실제 모델·사용자 자료가 생긴 뒤 확정한다. 현재 합성 테스트 통과로 임상적 타당성, 사용자 만족도, 출시 성능을 주장하지 않는다.

합성 비교에서는 콧볼 폭 오차 범위의 하한이 양 눈 안쪽 거리 오차 범위의 상한을 넘을 때만 좁힘을 비교할 수 있다. 두 범위가 맞닿거나 겹치거나 유효한 오차 범위가 없으면 방향을 보류한다. 공개 합성 GLB의 실제 점 후보·렌더 점검 결과는 [`real-glb-grounding-poc.md`](real-glb-grounding-poc.md)에 기록했다.

AI-578의 개발 생성 원본 3개에서는 49·279 후보가 모두 승인 리그의 콧볼 폭 기준점보다 안쪽에 있었다. 후보에서 계산한 비율은 반복 재현됐지만, 이 비율을 콧볼 폭 조건에 사용할 수 없다. 실제 모델의 첫 비교는 독립 참조로 콧볼 최외곽점과 오차 범위를 확인할 때까지 보류한다. [AI-578](https://ssafy.atlassian.net/browse/S15P31B204-578)

개발 생성 모델 3개의 승인 범위 안에서 콧볼 조절값 −0.05와 +0.05를 시험했다. 최종 피부 형상 검사는 6건 모두 통과했고, 조절값을 직렬화하고 다시 적용한 뒤에도 최종 정점 해시가 같았다. 별도 개발 검증 시안에서는 직접 조절로 −0.01을 적용해 저장하고, 새로고침 뒤 같은 값이 돌아오는 것을 확인했다. 되돌리기 후 다시 새로고침해 0이 유지됐다. 이 결과는 기존 조절·저장·이력 경로의 검증이며, 측정 근거로 첫 비교를 생성하는 제품 경로는 콧볼 참조점 검수 전까지 보류한다.

## 생성 시안 연결

서버의 `POST /api/v1/simulations/{simulationId}/first-comparison`은 소유자와 원본 상태를 확인하고, [저장된 검수 결과](../../design/baseline-measurements.md)의 콧볼 너비 하한이 눈 안쪽 거리 상한을 넘는 경우에만 후보를 검사한다. 참고 문헌의 해당 설명은 특정 전문가의 관찰이다. 제품에서는 두 부위를 함께 보는 3D 비교에만 사용한다. [Ethnicity and Nonsurgical Rhinoplasty](https://pmc.ncbi.nlm.nih.gov/articles/PMC9337225/)

콧볼 너비 조절값은 카탈로그와 모델 승인 범위 안에서 최대 −0.05로 제안하며 서버 형상 검사 결과를 사용한다. 미리보기 응답에는 시안 상태 버전, 조절 항목과 값, 설명, 출처가 있다. 표시할 수 없는 모델은 사유를 반환한다. 편집실의 첫 비교 버튼과 검수 대기 안내는 AI-660에서 제거한다. 개발 검증은 미리보기 API와 기존 편집 저장·조회·이력 경로를 사용한다.

검증 명령: `python -m unittest discover -s docs/ai/baseline-face-demo/scripts -p 'test_*.py'`.
