# 팀 논의안: 원본 3D 얼굴 분석에서 첫 수정 비교까지

2026-11-05 회의용 · AI-122/578/579 · **기술 설계안, 제품 출시 승인 아님**

## 먼저 합의할 사용자 경험

3D 생성이 끝나면 사용자가 질문하기 전에 **현재 얼굴의 확인 가능한 형태**를 쉬운 말로 설명한다. 이어서 그 얼굴에서 먼저 살펴볼 변화 한 가지를 이유와 함께 제시하고, **원본과 작은 비교 시안**을 같은 시점에서 보여 준다. 사용자는 비교를 닫거나 다른 조절을 고를 수 있다. 동의하기 전에는 원본과 편집 이력을 바꾸지 않는다.

> 예시: “정면에서는 광대에서 턱으로 갈수록 윤곽이 좁아지는 편이에요. 코는 양쪽 콧볼의 폭이 눈 안쪽 사이 거리보다 넓게 보입니다. 먼저 콧볼 너비를 조금 달리한 모습을 원본과 비교해 볼까요?”

이 문장은 **특징점·시점·출처·모델 지원·형상 검사**가 모두 통과한 사례에서만 쓴다. “더 예뻐진다”, “수술이 필요하다”, “전문의가 직접 진단했다”는 말은 쓰지 않는다. 조건이 모자라면 관찰 가능한 부분만 말하고 방향은 보류한다. 조절 근거가 약하지만 3D가 정상인 경우에는 한쪽 방향을 정답처럼 권하는 대신 **양방향의 작은 탐색 시안**을 제시하는 안을 회의에서 결정한다. 양방향 시안도 모델별 안전 범위와 형상 검사를 통과해야 한다.

> 보류 예시: “이 모델에서는 콧볼의 바깥 경계를 확실히 확인하지 못했어요. 코 너비를 단정해 설명하거나 방향을 정하지 않을게요. 원하시면 현재 가능한 조절을 직접 비교해 볼 수 있어요.” 직접 조절도 잠긴 모델에는 마지막 문장을 보이지 않는다.

## 현재 서비스에 있는 것과 없는 것

| 구간 | 현재 코드에서 확인한 것 | 이 기능에 아직 필요한 것 |
| --- | --- | --- |
| 3D 생성 | GLB·리그·모델별 코 승인 범위·형상 검증을 생성 결과와 결속한다. `qualityReport`에는 생성 품질·시간의 일부가 담긴다. | 분석에 쓸 해부학적 점과 **점별 신뢰도**는 별도 검증이 필요하다. |
| 코 계측 | `reconstruction/pipeline/evaluate.py`의 `nose_dims`는 코 높이·코끝·콧볼 주름 사이 거리를 실험적으로 계산한다. | 생성 워커 `app/reconstruction/worker.py`의 성공 보고에는 현재 `measurements`가 없다. DB 칼럼과 내부 결과 계약은 있지만 사용자 모델의 검증된 분석값으로 이어지지 않는다. |
| 특징점 의미 | `canonical.py`의 `alar_crease`는 주름의 오목한 점이다. | 문헌에서 콧볼 폭에 쓰는 `alare`는 **가장 바깥쪽 경계점**이다. 두 값을 같은 지표로 취급하지 않는다. 눈 안쪽점·광대·턱의 실제 GLB 대응도 대조해야 한다. |
| 상담 | Spring 상담은 GMS에 `measurements:{}`를 보낸다. 코 조절 4개와 모델별 허용 범위는 이미 있다. | 측정 계약(AI-122) 검증 전에는 수치를 상담에 넣지 않는다. 분석 결과는 기존 채팅과 목적·저장 시점을 구분한다. |
| 화면 | 기존 3D 비교 뷰어·슬라이더·저장·undo가 있다. | **생성 직후 분석 카드 → 근거 → 같은 카메라의 전후 시안 → 선택** 연결은 없다. |
| 비슷한 서비스 | “AI 관상”은 3D 완성 전 사진으로 보는 별도의 재미용 기능이다. | 이번 기능은 완성된 원본 3D의 **형태 관찰**이다. 관상 결과·사진·운세형 조언을 근거로 재사용하지 않는다. |

근거 경로: `worker.py`의 성공 결과, `ReconstructionWorkerService.java`의 측정 저장, `SpringConsultClient.java`의 빈 측정 문맥, `canonical.py`의 점 정의, `docs/design/face-reading.md`. “3D 생성 과정에서 계산한 값이 있다”와 “사용자에게 보여 줄 검증된 분석값이 있다”는 다른 상태다.

## 단계별 설계: 입력·출력·부족한 데이터·채우는 방법

| 단계 | 입력 → 출력 | 현재 부족한 것 | 채울 방법·검증 |
| --- | --- | --- | --- |
| 1. 원본 고정 | 성공한 원본 GLB·리그·메시 해시 → 분석 기준 모델 ID | 원본/편집 후 혼동, 구형 모델의 리그 누락 | 승인 정보의 메시·리그·엔진·위상 버전을 함께 저장한다. 분석은 **원본**에만 묶고, 재생성·삭제·버전 교체 때 캐시를 무효화한다. |
| 2. 특징점 추출 | 원본 3D → 눈 안쪽점, 콧볼 바깥점, 광대·턱, 코끝·코 시작점·턱끝 | `alar_crease`와 `alare` 불일치, 머리카락·비공·측면 가림, 좌우·축 혼동 | 필요한 점의 **해부학적 정의**를 먼저 고정한다. 현재 GLB 점 ID를 정면·45°·측면에서 수작업 대조하고, 불명확한 점은 사용하지 않는다. 영상 프레임과 메시의 같은 부위도 비교한다. |
| 3. 측정·품질 | 검증된 점·원본 해시 → 상대 치수·오차 범위·품질 상태 | 워커 성공 보고에 분석 치수 없음, 절대 mm는 실제 스케일이 아님 | AI-122와 한 계약으로 산식·좌우·단위·점별 품질·버전을 정한다. GLB의 눈 거리는 정규화된 63mm이며 실제 신체 mm가 아니므로 **무차원 비율**부터 쓴다. 측정값을 워커→Spring에 보내고 원본 해시에 묶어 재조회한다. 오차가 관계의 차이보다 크면 해석을 보류한다. |
| 4. 근거 선택 | 측정 ID·품질 → 허용된 문헌 카드·관찰 문장 | 개인별 정답을 뒷받침하는 자료가 없음 | `evidence-cards.json`의 출처·허용 용도·한계를 측정 ID로 조회한다. 소수의 검수 카드에는 검색형 RAG보다 **정확한 ID 조회**가 간단하고 검증 가능하다. GMS가 새 출처·숫자를 만들지 못하게 한다. |
| 5. 첫 비교 선택 | 관찰·문헌 조건·모델 capabilities → 비교할 조절 ID·방향 또는 보류 | 코끝·콧대·얼굴형의 개인별 방향 근거가 부족함 | 지금 출처의 콧볼 좁힘은 **합성 비교 가설**까지만 허용한다. 실제 모델은 점 정확도·개인 맥락·변화 가시성 검증 전 보류한다. 근거가 없는 조절은 자동 방향 추천 대신 양방향 탐색 시안 또는 무제안을 결정한다. 네 코 조절 중 지원하지 않는 값은 절대 고르지 않는다. |
| 6. 시안 렌더·검사 | 승인 범위 안의 작은 후보 → 같은 카메라의 Before/After | “작게”의 실제 3D 변화가 모델마다 다르고 비공 경계가 깨질 수 있음 | 기존 조절 엔진과 최종 메시 검사를 재사용한다. 정면·45°·측면에서 변화가 보이는지, 자기교차·비공·코 밖 변형이 없는지 확인한다. 후보가 실패하면 사용자는 원본만 본다. **적용 전에는 서버 편집 상태를 쓰지 않는다.** |
| 7. 선택·기록 | 사용자가 시안 선택 → 기존 편집 API·undo 1건 | 새 화면의 책임·저장 시점 미정 | FE는 원본/시안 전환과 근거 카드만 담당하고, 저장은 기존 BE 편집 API를 호출한다. 재조회·undo가 같은 모양을 재현하는지 확인한다. 분석 결과는 모델 해시·측정 버전·근거 버전을 함께 기록한다. |

## 근거 데이터의 실제 강도

1. [3D 특징점 정리](https://pmc.ncbi.nlm.nih.gov/articles/PMC13466362/)는 *어디를 잴지* 정한다. 자동으로 찾아낸 점이 정확하다는 증거는 아니다. [자동 3D 특징점 체계적 검토](https://pubmed.ncbi.nlm.nih.gov/37042196/)도 임상용 정확도에 주의를 요구한다.
2. [코 분석 10-7-5](https://pubmed.ncbi.nlm.nih.gov/32309081/)와 [얼굴형 전문가 합의](https://pubmed.ncbi.nlm.nih.gov/33144908/)는 관찰할 시점·부위를 정하는 데 쓴다. 후자는 산업계 원고 지원이 있으며 개인별 선호 목표를 제공하지 않는다.
3. [코끝·턱 관계](https://pmc.ncbi.nlm.nih.gov/articles/PMC3109328/)는 턱끝 위치를 모르면 코끝의 앞뒤 인상을 잘못 해석할 수 있음을 보여 준다. 따라서 코끝 자동 방향은 이 정보가 없을 때 보류한다.
4. [콧볼 폭 관련 전문가 의견](https://pmc.ncbi.nlm.nih.gov/articles/PMC9337225/)은 눈 안쪽 거리보다 넓은 경우 소폭 좁힘을 *검토*할 수 있다는 서술이다. 다른 시술 맥락의 의견이므로 사용자 3D에 −15% 같은 숫자를 옮기지 않는다. 문화·개인 선호도 다르다.
5. [미적 비율 근거 검토](https://pubmed.ncbi.nlm.nih.gov/37695808/)상 “정답 얼굴 비율” 상당수는 충분히 검증되지 않았다. 미모 점수나 전원에게 같은 목표값은 만들지 않는다.

**현재 보유 데이터:** 짧은 재서술·출처·허용 용도·한계가 들어 있는 문헌 카드 9개, 도식 합성 3D 1종, 공개 합성 GLB 2종의 점 후보·전후 렌더, 기존 코 승인 범위·형상 검사. **부족한 데이터:** 검증된 실제 생성 모델의 해부학적 점, 점별 오차, 다양한 얼굴에서의 시안 외관, 초보 사용자의 이해·선호. 전문가가 각 실제 얼굴에 표시한 정답이나 수술 결과 데이터는 없다. 그래서 현 단계에서 파인튜닝은 하지 않는다. 공개 논문은 관찰 규칙으로만 쓰고 전문·사진을 학습 데이터처럼 수집하지 않는다. 실제 GLB PoC는 [`real-glb-grounding-poc.md`](real-glb-grounding-poc.md)에 기록했다.

| 데이터 후보 | 실제 쓸 곳 | 확보·사용 판단 |
| --- | --- | --- |
| 기존 생성 GLB·리그·원본 영상의 5시점 프레임 | **우리 파이프라인의** 점·형상 검증 | 해당 사용자의 허가와 현행 보관 범위 안에서만 QA. 얼굴 자료는 Jira·MR·GMS에 복사하지 않고, 점 위치·오차 집계만 남긴다. |
| 수식 기반 합성 얼굴·기본 모델 | 누락·오류·방향 반전의 자동 회귀 | 바로 사용 가능. 실제 얼굴의 외관 품질을 증명하지 못한다. |
| [MediaPipe 468점](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/face_mesh.md)과 현재 GLB의 점 ID | 초기 후보 위치 탐색 | 얼굴 랜드마크의 좌표 체계와 인덱스다. 문헌의 `alare` 등 해부학적 점으로 **그대로 간주하지 않는다**. |
| [FaceBase 3D Facial Norms](https://trackhub.facebase.org/resources/human/facial_norms/notes/) | 측정법·사람 간 변이 참고 | 요약 통계는 참고할 수 있지만 개인별 3D는 접근 승인·사용 조건이 필요하다. 개인의 정답 목표값으로 쓰지 않는다. |
| [FaceScape](https://nju-3dv.github.io/projects/FaceScape/static/license/LicenseAgreement_FaceScape.pdf) | 이번 제품에는 사용하지 않음 | 비상업 연구용·신청 자격 제한이 있어 사용자 기능의 학습·검증 원본으로 가져오지 않는다. |

미래의 “비슷한 사람들이 주로 바꾼 방향”은 **의학 문헌도 이 표의 얼굴 데이터도 아니다.** AI-580의 별도 동의·집계·표본 부족 기준이 마련되기 전에는 첫 비교의 근거로 섞지 않는다.

## 최소 계약 초안

```json
{
  "modelId": "<사용자 소유 모델>",
  "sourceMeshSha256": "<원본 해시>",
  "rigVersion": "<리그 버전>",
  "measurementVersion": "v1",
  "evidenceVersion": "2026-11-04-v1",
  "observations": [{"metricId": "alar_to_inner_eye", "quality": "verified", "evidenceId": "NOSE_LANDMARKS"}],
  "firstComparison": {"status": "deferred|exploratory", "control": "nose.alar_width", "direction": "narrow", "amount": null, "applied": false}
}
```

이는 **논의용 응답 모양**이며 확정 API가 아니다. FE에 보여 줄 설명은 승인된 수치·문장 템플릿으로 조립한다. 실제 사용자 얼굴의 사진·영상·GLB·3D 렌더를 GMS에 보내지 않는다(REQ-N-10). 현재 합성 GMS 시험은 실제 사용자 전송 권한을 뜻하지 않는다. 측정값도 AI-122의 전송 조건이 정해지기 전에는 GMS에 넣지 않는다. 설명은 우선 서버의 고정 문장으로 구현하고, 말투 다양화가 필요할 때만 허용 ID·숫자를 다시 검증하는 GMS를 검토한다.

## 검증 계획과 통과 판단

| 시험 자료 | 확인할 것 | 실패 판정 |
| --- | --- | --- |
| 합성·경계 시나리오 | 출처 누락·잘못된 ID·NaN·방향 반전·미지원 조절·프롬프트 주입·형상 실패 | 출처 없는 문장이나 자동 적용이 한 번이라도 나타나면 실패 |

| 원본/시안 회귀 | 4개 코 조절의 방향·범위, 비공 경계, 코 밖 변형, 저장·재조회·undo | 깨진 메시·잘못된 부위·값 불일치 시 후보 노출 실패 |
| 초보 사용자 **10명 제안** | 설명 이해, 첫 비교가 선택에 도움 되는지, “의료 권유”로 오해하는지 | 오해가 반복되면 문구·흐름 수정. 선호도만으로 의학적 정확성을 주장하지 않음 |
| 시간·비용 | 3D 완료→분석 표시, 후보 검사→전후 표시 p50/p95·GMS 사용량 | 목표 수치는 첫 실측 후 팀이 확정. 캐시 재조회는 재계산하지 않음 |

20개·10명은 **회의에서 정할 평가 규모 제안**이며 검증된 표본 크기나 현재 확보 건수가 아니다. 실제 얼굴·동영상·서명 URL은 Jira·MR·외부 AI 평가 기록에 넣지 않는다. 원본 모델은 기존 권한·보관·삭제 정책을 따른다.

속도 설계: 3D 완료 화면을 분석 때문에 막지 않는다. 같은 원본 해시·측정/근거 버전의 분석은 재계산하지 않고, 첫 분석이 늦거나 GMS가 실패하면 검증된 고정 문장만 먼저 보여 준다. 후보 3D는 기존 morph 엔진으로 만들되 **표시 전에 한 번** 서버 형상 검사를 하고, 사용자가 선택하면 기존 저장 API로 확정한다. 합성 GMS 한 사례에서 Luna 호출은 약 2.8초·공유 잔액 관측 차이 2크레딧이었지만, 이는 사용자 모델의 p95·확정 과금이 아니다. 후보 검사·화면 표시를 포함한 단계별 실제 p50/p95와 비용을 따로 재야 한다.

## 내일 결정할 네 가지

1. **첫 출시 범위:** 코의 정면 관찰과 안전한 첫 비교만 먼저 내고, 얼굴형은 검증된 윤곽 설명까지 둘지. 권장: 얼굴형 이름·점수 없이 설명부터 시작한다.
2. **근거가 약한 경우:** 자동으로 한 방향을 정할지, 안전한 양방향 탐색을 보여 줄지. 권장: 방향을 지어내지 않고 양방향 또는 보류한다.
3. **측정 계약:** 누가 `alare`·눈 안쪽점·광대·턱을 최종 GLB에서 검증하고, 점별 품질·오차·원본 해시를 AI-122/578에 넣을지. 이 결정이 첫 선행 작업이다.
4. **출시 표현·전송:** 이름을 “문헌을 참고한 3D 얼굴 분석”으로 하고, 관상과 분리하며, 실제 얼굴 이미지의 GMS 전송은 열지 않을지. 권장: 현행 제한을 유지한다.

## 실행 순서와 담당 영역

1. **AI·3D / AI-122·578:** 최종 GLB 특징점 정의·샘플 대조·측정 버전/오차/품질 계약. 현재 생성 워커의 빈 `measurements` 경로를 채우기 전에 실제 점을 먼저 확인한다.
2. **AI / AI-579:** 문헌 카드와 관찰·방향 정책, 실패 시 보류, 합성·실제 모델 회귀셋. 현재 합성 게이트는 [설계 검토](first-comparison-design-review.md)와 18개 테스트로만 검증됐다.
3. **BE:** 모델 해시·근거 버전 결속, 소유자만 조회, 캐시 무효화, 후보 형상 검사, 기존 저장·undo와 연결. GMS는 필요할 때만 별도 관찰 경로로 호출한다.
4. **FE:** 3D 완성 후 분석 카드, 근거 보기, 같은 각도의 전후 비교, 사용자의 명시적 선택. 기존 “AI 관상” 화면과 이름·시점을 구분한다.
5. **공동 QA:** 다양한 생성 모델·초보 사용자·지연/비용 평가 후 출시 여부를 결정한다. 각 단계에서 불확실하면 그 부분만 숨기고 이미 검증된 3D 편집은 유지한다.
