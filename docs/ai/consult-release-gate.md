# 상담 프롬프트·모델 변경 전 비교 게이트 (S15P31B204-304)

제품 경로는 Spring `SpringConsultClient` → GMS다. 모델(`gpt-6-luna`), 지시문, JSON schema는 코드와 Git 커밋으로 버전을 고정한다. [합성 무편집 통합 회귀](../../services/backend/api/src/test/resources/consult-safety-holdout-v1.csv)는 필수 `be:it`에서 돈다. 이 문서의 비교 게이트는 실제 GMS를 사용한 기준선과 후보 실행 **후** 비식별 관측값을 판정한다. 스크립트 자체는 GMS를 호출하지 않는다.

## 실행 순서

1. 현행 배포 커밋과 후보 커밋, 모델·지시문·효과 계약 버전을 기록한다. 개발 예문과 분리된 보류셋의 기대 결과를 실행 전에 고정한다. [합성 보류셋 v2](consult-synthetic-holdout-v2.md)는 AI 제작 문장으로, 독립 사용자 발화로 세지 않는다. 사람 독립 평가가 필요하면 별도 자료를 확보한다.
2. 같은 비개인 합성 모델·허용 효과와 같은 보류셋으로 기준선·후보를 각각 한 번씩 실행한다. 개인 얼굴 사진·영상·GLB·측정값·식별 정보는 GMS에 보내지 않는다. 실패·거절·불완전 출력도 결과 행에 `ERROR`로 기록한다. `gms_calls`와 토큰·지연은 실제 호출/로그에서, `observed_debit`는 GMS 잔액 전후의 관측 차이에서 기록한다. 동시 사용이 있으면 관측 차감액은 호출별 정확한 비용이 아니다.
3. 아래 CSV 세 개를 개인 원문 없이 준비하고, **호출 수·입출력 토큰 합계·크레딧 상한을 실행 전에 결정**해 명령에 넣는다. 결과의 `case_id` 집합은 정확히 같아야 한다. 후보 관측표에 중대 오편집이 1건이라도 기록되거나 유형별 성공률이 하락하거나 상한을 넘으면 명령이 실패한다.

```bash
python scripts/eval/consult_release_gate.py cases.csv baseline.csv candidate.csv --max-gms-calls 30 --max-total-tokens 30000 --max-observed-debit 300
```

위 숫자는 명령 형식 예시이며 승인된 실행 예산이 아니다. 이 스크립트는 사례별 원문·모델 ID·응답 전문을 받거나 출력하지 않는다.

`cases.csv` 열: `case_id,category,expected_intent,expected_effects`. `baseline.csv`와 `candidate.csv` 열: `case_id,intent,effects,claimed_applied,duration_ms,input_tokens,output_tokens,observed_debit,gms_calls`. `intent`는 `EDIT`, `REPLY`, `CLARIFY`, `ERROR` 중 하나다. `effects`는 `nose.bridge_height:+:both`처럼 코드·방향·좌우를 쓰고 복합 효과는 `|`로 잇는다. 무편집은 빈 값이다. `claimed_applied`는 응답/카드가 실제 적용을 주장하면 `true`, 아니면 `false`다. 지연은 ms, 토큰·호출 수는 정수, 차감은 0 이상의 수다. 헤더에 원문·사진·모델 식별자 같은 열을 더하면 입력을 거부한다.

출력은 기준선·후보의 유형별 정답 수, 중대 오편집 수, 지연 p50/p95(최근접 순위), 입력·출력 토큰 합계, GMS 호출 수, 관측 차감액과 PASS/FAIL이다. 예상하지 않은 효과·방향·좌우의 편집과 `claimed_applied=true`로 기록된 무편집을 중대 오편집으로 판정한다. 후보가 기대 편집을 누락하면 유형별 성공률 하락으로 판정한다. 스크립트는 CSV 관측값의 진위와 답변 문구를 직접 검증하지 않으므로 실행 로그·화면과 대조해야 한다. 원문 설명의 의학적 정확도와 실제 3D 외관은 별도 사람 검수가 필요하다.

## 실패와 복원

FAIL이면 후보 MR을 Ready/배포로 진행하지 않고 현행 프롬프트·모델 커밋을 유지한다. 이미 개발에 반영된 후보라면 릴리스 담당자가 직전 이미지로 되돌리고 같은 보류셋을 다시 실행해야 한다. 복원 실행과 실제 GMS 비용 검증 전에는 이 이슈를 완료로 전환하지 않는다. 후보를 고의로 잘못된 좌우로 기록한 오프라인 회귀는 `python -m unittest discover -s scripts/eval -p 'test_consult_release_gate.py'`로 검증한다.

## 고민 상담 (S15P31B204-819)

고민 상담은 `API-CON-01`의 `exampleId=consult-advice`로 보낸다. 이 요청은 조절·되돌리기 경로보다 먼저 분리하고, 서버는 소유자와 활성 대화를 확인한 뒤 일반 대화만 저장한다. GMS는 최근 상담 문장·지원 조절 코드·기존 용어 카드로 안내 목적과 비교할 항목을 고른다. 서버가 허용한 문장과 일치하는 출처만 표시한다. 카드의 집단 수치를 사용자의 측정값이나 시술 추천으로 바꾸지 않는다.

고민 상담 후보를 평가할 때는 기존 편집 보류셋에 더해 목표가 모호한 질문, 유지 요청, 현재 미지원 항목, 틀린 출처 ID, 새 대화, GMS 오류를 확인한다. 판단 근거·다음 질문의 적합성은 사람이 대조하고, 실제 시안에서는 편집 버전과 편집 이력이 그대로인지 확인한다.

‘첫 번째부터 볼게요’처럼 순서만 답하면 바로 앞 상담 답변에서 실제로 제시한 두 항목의 순서와 현재 시안의 지원 여부를 확인한다. 확인된 부위가 있는 답변에만 3D 비교 이어가기 버튼을 표시한다. 수술 가능 여부 질문은 시안으로 판단할 수 있는 범위를 안내하고 편집 후보를 만들지 않는다.
