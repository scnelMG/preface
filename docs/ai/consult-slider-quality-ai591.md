# 채팅 조절·응답 품질 검증 (S15P31B204-591)

## 범위와 판정

직접 조절의 코 4종, 눈 5종, 윤곽 6종, 체중 변화 방향 1종을 대상으로 사용법 질문과 양방향 편집 요청을 합성 문장으로 검사했다. 쌍꺼풀 모양 선택은 슬라이더가 아닌 별도 선택 항목이며 기존 상담 검증을 유지한다. 모델마다 검증된 효과 코드만 안내·후보에 넣고, 채팅은 후보를 만든 뒤 사용자가 적용할 때 저장한다. 눈은 양쪽 함께, 체중 변화는 단독 적용이다.

응답 품질은 정확한 부위·방향, 모델별 지원 범위, 무편집 사실, `~요` 말투, 의료 판단·내부 정보·무관한 질문의 거절을 따로 확인했다. 비결정적 요청은 GMS가 구조화된 후보를 만들더라도 서버에서 허용 코드·원문 근거·좌우·방향을 다시 검증한다. 이 평가는 [평가 사례를 먼저 고정하고 실패 유형을 나누는 방법](https://developers.openai.com/api/docs/guides/evaluation-best-practices)과 [입출력 검증·안전한 거절](https://developers.openai.com/api/docs/guides/safety-best-practices)을 참고했다.

AI-596부터 허용 코드는 **모델 승인과 현재 시안 상태를 함께** 반영한다. 체중 변화 가중치가 0이 아니면 채팅도 체중 변화만 후보로 만들고, 다른 눈·코·윤곽·점 편집이 있으면 체중 변화 후보를 잠근다. 잠긴 항목을 물으면 원본으로 돌리는 방법과 무편집 사실을 안내한다. 시안이 질문과 적용 사이에 바뀔 수 있으므로 저장 단계의 기존 상태·형상 검증도 유지한다.

AI-603은 체중 변화 중 다른 부위로 옮기는 동작을 [체중 변화 형상·저장 기준](weight-shape-validation.md)에 따라 바꿨다. 상담의 다른 부위 편집 후보는 다시 허용하고, 적용 단계에서 체중 원복과 새 편집을 한 이력으로 묶는다. 다른 편집이 있는 상태에서 체중 변화 요청을 막는 규칙은 유지한다.

AI-606은 윤곽 채팅의 허용 코드를 해당 모델의 승인 해시와 실제 GLB의 양방향 변형 타깃에 맞춘다. 생성 모델의 채팅 요청과 저장 전 검사에서 같은 모델·자산·승인 결속을 다시 확인한다. 확인되지 않은 윤곽 요청은 후보나 이력을 만들지 않고 이유와 무편집 사실을 안내한다. 3D 조회는 DB 행 잠금 밖에서 하고, 실패 시 이번 요청의 윤곽 코드를 허용하지 않는다.

AI-609부터 일반 윤곽 코드는 체중 변화 승인과 독립적으로 검사한다. 현재 모델의 GLB 형식·생성 메타데이터·실제 양방향 타깃을 확인하고, 코나 체중 승인 정보가 있다면 현재 GLB의 해시·fit과도 대조한다. 채팅 요청과 적용 직전에 각각 다시 검사하며, 확인할 수 없는 코드는 후보와 저장을 막는다. 체중 변화 코드는 기존 별도 승인과 단독 편집 검사를 유지한다.

AI-612는 감량·증량한 **모습을 보여 달라는 요청**을 체중 변화 미리보기 편집으로 처리한다. 실제 kg 수치로 개인의 얼굴을 묻는 질문은 무편집 안내를 유지하고, 다른 부위 편집이 남아 있으면 미리보기 요청도 기존 단독 적용 규칙으로 막는다. 이 분기는 Spring의 결정적 문장 해석이며 GMS 지시문은 바꾸지 않았다.

AI-603의 프롬프트 변경은 비개인 합성 4문장(코·눈·윤곽 편집 3, 복합 거절 1)을 체중 변화가 켜진 동일 상태·허용 코드로 현행 `main`과 후보에 각각 GMS 4회씩 보냈다. 개인 원문·키·응답 전문은 보관하지 않았다. 편집 효과·방향은 두 버전 모두 3/3, 복합 거절 1/1, 중대 오편집 0건이었다. `claimed_applied`는 GMS의 편집 후보와 별도 통합 테스트의 저장 성공을 합쳐 기록했다. 후보의 입력·출력 토큰은 5443·753, 호출 4회, 관측 차감 9크레딧이며 기준선은 5255·752, 4회, 9크레딧이었다. 호출 8회·합계 15000토큰·관측 차감 30크레딧 상한에서 비교 게이트가 PASS했다. 이 비교는 같은 허용 코드를 준 **프롬프트 영향만** 분리한 결과이며, 실제 기준선의 상태별 허용 코드 차이는 회귀 테스트로 확인했다.

## 적용한 상담 편집 정정

‘콧대는 그대로 두고 아까 바꾼 코끝만 되돌려줘’처럼 부위가 지정된 정정은 서버가 현재 시안의 활성 이력에서 해당 항목을 찾는다. 해당 항목의 가장 최근 변경이 상담 편집인 경우에만 직전 값을 복원한다. 코끝 위아래의 높이와 회전은 한 조절로 복원한다. 대상이 모호하면 복원할 수 있는 항목을 보여 준다. ‘아까 거 조금만 줄여줘’의 선택지는 기존 값에서 직전 값 쪽으로 변경량의 4분의 1만 되돌린다.

후보와 선택지를 만들 때 시안 버전을 기록한다. 이후 값이 바뀐 시안은 이전 후보로 편집할 수 없다. 기존 형상 검사와 모드 제한을 적용하고, 요청한 값이 검사 결과와 달라지면 정정을 보류한다. 통과한 정정은 한 이력으로 저장한다.

## 모호한 요청과 조절 안내

시안에서 실제로 열려 있는 조절을 기준으로 되묻기 문장과 버튼을 만든다. 안내 버튼은 조절 방향을 설명하며 편집 후보나 이력을 만들지 않는다. 시안이 바뀌면 이전 선택지는 만료된다. 사용자가 대상과 방향을 명확히 요청하면 기존 상담 적용 흐름으로 이어진다.

안내에서 항목을 고른 직후에는 ‘그럼 조금 올려줘’처럼 방향이 분명한 한 문장을 고른 항목에 연결한다. 방향을 말하지 않거나 고른 조절이 지원하지 않는 방향이면 조절법을 다시 안내한다. 다음 대화가 이미 저장됐거나 시안 버전이 달라졌으면 그 선택을 사용하지 않는다. 후속 후보에도 버전을 기록해 적용 직전까지 확인한다.

## 모델별 편집 범위

시안의 직접 조절은 [공통 모델별 범위](../../contracts/edit/effects-v1.md)와 렌더러가 확인한 타깃을 함께 사용한다. 상담은 같은 모델별 범위에서 지원 코드를 고르고, 현재 모드와 눈 상태에 따라 편집 후보를 제한한다. 모델에서 지원하더라도 체중 변화 때문에 잠긴 항목에는 모드 전환을 안내한다. 이전 서버 응답에는 기존 승인 필드를 적용한다. 최종 저장은 각 효과의 기존 범위와 형상 검사로 제한한다.
