# 유사 집단 조절 경향: 합성 자료 타당성 검증 (S15P31B204-580)

> 최종 갱신: 2026-11-04
>
> 판정: **실제 이용자 통계 기능 도입 보류**. 이 문서는 데이터 수집·화면 공개·운영 집계의 승인 문서가 아니다.

## 범위와 현재 근거

[요구사항 REQ-F-02·03, REQ-N-01·02](../planning/01_요구사항정의서_v2.7.md)와 [FN-AUTH-03·04](../planning/01_기능명세서_v2.7.md)는 얼굴 데이터의 동의·삭제 경계를 정한다. 현재 [얼굴 데이터 동의](../../apps/web/src/features/legal/documents/faceData.ts)와 [개인정보 처리방침](../../apps/web/src/features/legal/documents/privacyPolicy.ts)에는 다른 이용자의 얼굴 범주와 편집 선택을 묶어 유사 집단 통계를 만들고 제공하는 목적·항목·보관 조건이 명시돼 있지 않다. 얼굴 공개 동의도 현재는 본인만 접근하는 [범위](../../apps/web/src/features/legal/documents/facePublic.ts)를 설명한다. 그러므로 이 실험에 실제 얼굴, 시안, 행동 기록, 계정 식별자를 쓰지 않았다. 기존 동의를 이 목적의 허가로 해석하지 않는다.

이슈의 목적은 통계 카드의 **가능 조건**을 검토하는 것이다. 전문가 근거로 만든 첫 시안(관련: S15P31B204-576·578·579)과 이용자가 무엇을 눌러 보았는지에 대한 집계는 출처와 의미가 다르다. 집계의 선택은 미적 적합성, 만족도, 지속 선택, 시술 효과나 권고의 증거가 아니다.

## 수집 전 검토할 최소 이벤트 계약 초안

아래는 실제 저장 스키마가 아니라 개인정보·기획 검토용 항목 목록이다. **합성 스크립트의 `subject`·`account`는 모두 임의 문자이며 실제 사용자 연결 방법을 확정하지 않는다.**

| 항목 | 목적·제한 |
| --- | --- |
| 별도 목적 동의 상태·버전과 철회 연결 키 | 해당 통계 목적에 명시적으로 동의한 집계 대상만 넣고 철회·탈퇴 때 관련 이벤트와 캐시를 제거한다. 실제 키 방식, 보관 기간과 백업 파기는 검토 전 미정이다. |
| 검증된 거친 얼굴 특징 범주와 **범주 버전** | 특징 범주 정의·재식별 위험을 검증한 뒤에만 사용한다. 얼굴 원본·영상·사진·3D 메시·랜드마크·개별 좌표를 이 통계용으로 추가 수집하지 않는다. 범주가 식별에 기여할 수 있으므로 그 자체를 익명으로 간주하지 않는다. |
| 모델 버전·화면 버전, 표시 묶음 키, 후보 코드·표시 순서 | 실제로 보인 후보를 분모로 삼고 버전과 순서별로 비교한다. 후보의 얼굴 형상이나 렌더 이미지는 저장하지 않는다. |
| `shown`·`try`·`undo`와 동일 표시 묶음 연결 키 | 한 사람이 본 후보, 시험 적용, 되돌린 사실만 연결한다. 한 번 시험한 사람은 같은 후보를 여러 번 눌러도 한 번만 센다. 되돌리기는 시험 기록과 구분하며 `try`를 만족·선호로 바꾸지 않는다. |

중복 계정은 계정 수로 사람 수를 대체하면 통계를 왜곡한다. 합성 자료에서는 같은 `subject`에 계정 두 개를 넣어 중복 제거를 확인한다. 운영에서 이를 해결할 신뢰 가능한 방법은 아직 없다. 얼굴 매칭이나 기기 지문으로 억지로 연결하지 않는다. 중복을 통제할 수 없으면 카드를 보류한다. 원본 이벤트와 집계는 개인 삭제·동의 철회를 반영할 수 있어야 하며, 집계가 불가역적으로 퍼진 뒤의 회수 문제도 검토해야 한다.

## 재현과 관찰

저장소 루트에서 표준 라이브러리만으로 실행한다.

```sh
python scripts/eval/similar_cohort_synthetic.py
python -m unittest discover -s scripts/eval -p test_similar_cohort_synthetic.py -v
```

스크립트는 코드 안에서 만든 가상 `s1`~`s8`만 다룬다. 출력의 `illustrative 5`는 **억제 동작을 시험하기 위한 임의 입력값**이며 실제 최소 표본·공개 기준이 아니다. 실제 기준은 분포, 재식별·차분 공격, 반복 조회, 불확실성을 검토해 별도로 결정한다. `suppressed` 셀은 후보별 수치뿐 아니라 정확한 집단 크기도 출력하지 않는다. `test-only-pass`는 제품 공개 승인이라는 뜻이 아니다.

| 합성 사례 | 재현 결과 | 판단 |
| --- | --- | --- |
| 작은 집단 | 서로 다른 가상 주체 4명으로 구성. `suppressed` | 크기와 후보별 수치 모두 비표시 |
| 중복 계정 | 계정 5개처럼 보여도 가상 주체는 4명. `suppressed` | 계정 수를 표본 크기로 쓰지 않음. 실제 연결 방법은 미해결 |
| 모델·화면 버전 | 각각 3명씩 두 버전으로 나뉨. 각 셀 `suppressed` | 버전을 합쳐 표본 부족을 가리지 않음 |
| 동의 누락·철회 | 동의 없는 1명 제외 또는 1명 철회 후 모두 `suppressed` | 이미 계산한 값을 재사용하지 않고 다시 계산. 실제 게시물 회수 방식은 미해결 |
| 제시 순서·되돌리기 | 8명 모두 첫 번째 후보를 시험. A를 먼저 본 6명은 A, B를 먼저 본 2명은 B를 시험해 A 6건·B 2건처럼 보이나 `order-confounded`. A 시험 1건은 되돌림 | 노출 순서만으로 생긴 차이를 ‘선호’로 읽거나 게시하지 않음. 되돌림은 별도 진단 |

위 숫자는 전부 의도적으로 만든 예시다. 가상 사례에서 소규모 억제와 버전 분리, 철회 후 재계산이 동작함을 확인한 결과만 말할 수 있다. 실제 이용자 집단의 크기, 성향, 선택 편향의 크기, 통계적 신뢰도는 전혀 추정할 수 없다.

## 화면 문구와 도입 조건

도입 검토 시 집계는 전문가 첫 시안과 **별도 카드**에 두고, “비슷한 특징 범주의 이용자가 시험해 본 변경”처럼 관찰 행동만 설명한다. 표본·편향 조건을 통과하지 못하면 카드를 표시하지 않는다. “전문가가 권하는 방향”, “더 예뻐지는 방향”, “효과가 좋은 시술”처럼 결과·의학적 판단으로 읽히는 문구는 쓰지 않는다. 현재는 카드를 표시할 근거가 없어 문구도 제품에 연결하지 않는다.

실제 도입은 다음 조건이 모두 충족된 뒤 별도 결정한다.

1. 개인정보·기획 담당이 집계 목적의 별도 고지·동의, 이용 항목, 보관 기한, 철회·탈퇴·백업·캐시 삭제 절차를 검토하고 승인한다.
2. 범주 정의와 버전이 재현 가능하며 식별·차분 노출 위험을 평가한다. 반복 조회와 겹치는 집단의 비교까지 포함해 공개 기준을 정한다.
3. 신뢰할 수 있는 중복 통제와 제시 순서의 균형 배치·평가 계획을 마련한다. 실제 동의 표본에서 버전별 노출 분모, 시험·되돌림, 순서별 차이를 검증한다. 표본이 부족하면 계속 비표시한다.
4. 전문가 근거형 첫 시안과 카드 문구를 분리해 사용자 이해도·오해 가능성을 검수한다. 운영 도입·실제 이벤트 수집은 이 검증과 별도 작업으로 승인한다.
