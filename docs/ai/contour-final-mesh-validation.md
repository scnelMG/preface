# 윤곽 모프 최종 메시 안전 검사 (S15P31B204-616)

> 최종 갱신: 2026-11-16 · 판정: 새 생성 레시피의 안전한 단독 방향만 굽는다. 동시 편집 출시 보류.

## 원인과 수정

AI-615의 원본 대비 검사는 공개 기본 남녀 GLB의 단독 윤곽에도 새 자기교차를 찾았다. 삼각형 쌍 위치를 비식별·합성 좌표로 확인하니 입술 경계 주위였다. 이전 윤곽 생성기는 각 타깃의 면 뒤집힘·면적만 확인했으며, 피부 전체의 자기교차는 검사하지 않았다.

`contour_morphs.py`에서 입꼬리 두 랜드마크를 잇는 선으로부터 **템플릿 좌표 기준** 10 mm 안의 윤곽 변위를 0으로, 20 mm까지 부드럽게 복원한다. 이는 입술 경계를 보호하는 **기하학적 완충 거리**이지 수술·체중 변화의 실측 범위가 아니다. 각 윤곽 코드의 양방향 끝값을 원본 대비 최종 피부에서 검사하고 한 방향이라도 불합격이면 그 코드의 타깃 쌍을 모두 생략한다. 안전한 다른 코드와 별도 형상 검사를 통과한 체중 타깃은 유지한다. 보호할 입꼬리 랜드마크가 없으면 새 윤곽 타깃을 굽지 않는다.

공개 기본 GLB는 중립 정점·기존 코 타깃·체중 타깃·텍스처가 그대로이고 윤곽 타깃만 다시 구웠다. 여섯 코드의 끝값 최대 변위는 수정 전과 동일했다. 새 파일은 남성 `c856a88dd70667f9be3e17c5eaa3d65760eedfd504a7bf4319ec6ca31bbca1c5`, 여성 `ab4e4d37809b382531ba923e19d7d634c38e93aae027a7265c8a4b3d685d7931` SHA-256에 결속한다. 눈 한계를 새 파일로 재계산한 결과 기존 값과 같았다. 로컬 체험 화면에서 남성 광대 양 끝·턱끝 길이 끝값, 여성 광대 축소 끝값과 원복을 확인했다. 사선 시점에서 입술 경계의 뚜렷한 찢어짐은 보이지 않았다.

공개 기본 모델의 눈·코 보호 마스크 안 윤곽 변위는 수정 전과 바이트상 동일했다. 다만 기존 광대 모프가 넓게 잡힌 눈 마스크를 끝값에서 약 1.9 mm 움직인다. 이 수치는 눈꺼풀 안전 승인으로 해석하지 않으며 눈+윤곽 복합 편집은 계속 잠근다.

생성 모델 검사는 개발의 승인된 비공개 GLB 세 개를 임시로 읽어 기존 윤곽 참조만 제외한 **새 생성 경로의 후보**에서 수행했다. 후보의 중립 정점과 기존 바이너리·타깃은 그대로였다. 후보는 S3·DB에 쓰지 않았고 서버와 로컬의 비공개 임시 파일은 검사 후 삭제했다. 이 세 표본은 전체 생성 모델의 안전성을 증명하지 않는다.

## 가까운 표면의 광대·사각턱 변위

AI-898에서는 실제 피부 메시를 템플릿 좌표계에 정렬한 뒤 각 정점의 광대·사각턱 변위를 반경 3 mm 안의 정점과 거리 가중 평균한다. 메시에서 연결되지 않은 표면도 3D 위치가 가까우면 비슷하게 움직인다. 평활화 이후 눈·코와 입술 경계의 보호 감쇠를 적용하고 결과를 기존 방향별 검사에 넣는다.

0.18 mm 떨어진 두 합성 표면에서 양방향 통과 배율이 0.1에서 1로 늘었다. GNM 합성 평균 머리를 굽기 전후로 비교했을 때 광대의 음·양 방향은 각각 0.5·0.05에서 모두 1로 늘었고 사각턱과 체중은 양방향 1을 유지했다. 체중 검사에 같은 합성 표면의 평활화 전 변위를 넣으면 새 자기교차로 양방향이 0.1배로 줄어든다. 실제 생성 모델에서의 개선 폭과 체중 변화의 축소 원인은 별도 확인이 필요하다.

## 출시 경계

격자는 세 슬라이더가 **같은 강도**일 때의 네 표본값이다. 서로 다른 임의 값, 윤곽 세 항목 이상, 눈·코와의 복합 최종 피부, 정면·측면·아래 및 생성 얼굴의 시각적 자연스러움은 승인되지 않았다. 공개 기본 모델의 기존 코 GLB 모프 5종은 단독의 한쪽 끝값에서도 원본 대비 자기교차가 검출됐다. 코 문제는 이 윤곽 레시피 수정 범위에 포함하지 않는다. 체중과 다른 부위의 동시 편집 잠금은 유지한다.

기존 생성 자산은 바꾸지 않았다. 기존 모델까지 수정하려면 원본 자산 보존, 새 GLB의 코·눈·체중 승인 해시 재결속, 시안 이력·undo 유지, 삭제 예약과 실패 복구를 별도 배치로 검증해야 한다. 안전한 코드가 모델마다 다를 수 있으므로 서버·채팅·화면은 새 GLB의 실제 양방향 타깃 쌍을 기준으로 지원 여부를 표시해야 한다.
