# AI 실장님 눈·코 용어 근거와 검색 판정 (S15P31B204-74)

2026-10-27. 이 문서는 FN-CON-03·REQ-F-12의 **검색 방식 검증 결과**다. [용어 카드](../../services/backend/api/src/main/resources/consult-terms-v1.json)의 14개 카드는 제품의 편집 허가 목록이 아니다. 효과 의미·코드의 기준은 [눈·코 효과 계약](../../contracts/edit/effects-v1.md)이며, 1차 실제 편집은 검증된 코 모델의 `capabilities`에 있는 효과만 허용한다. 눈 효과와 콧구멍 테두리 모양은 현재 편집할 수 없다. 검색 결과나 연구의 평균치는 개인 얼굴의 진단·수술 적합성·안전 범위가 될 수 없다.

## 카드 사용 기준

각 카드는 용어의 뜻, 다른 의미일 때 할 질문, **가능한 조절 코드 후보**, 1차 지원 여부, 출처를 분리한다. 후보 코드는 검색이 맞아도 바로 `actions[]`로 변환하지 않는다. 사용자의 실제 편집 의도·방향·부위가 명확하고 현재 모델의 지원 목록과 서버 형상 검사를 통과해야 한다. 특히 인라인·인아웃·아웃라인은 쌍꺼풀 **선 형태**라 `eye.double_lid_depth`(기존 홈 진하기)로 대체하지 않고, 비공/콧구멍 테두리는 `nose.alar_width`로 대체하지 않는다. 코끝의 돌출·높이·회전과 콧볼 폭·벌어짐도 한 말로 합치지 않는다.

카드 14개 중 E01–E06은 눈 용어, N01–N08은 코 용어다. 기존 카드의 `reviewer`와 `reviewDate`는 2026-10-27, N06–N08은 2026-10-31에 Codex가 **출처·효과 계약을 1차 대조**한 기록이다. `clinicalReview: false`는 전문가·제품 검수 전을 뜻한다. 카드 문장은 설명용 초안이며, 임상 효과·권장 수치·수술법을 담지 않았다. 제품 답변에 넣기 전에는 담당자가 표현·현재 모델 지원 여부를 다시 검수하고, 의료 판단 문구를 추가하려면 자격 있는 검토자가 확인해야 한다.

| 용어 질문 | “인아웃 라인이 뭐야?” | 선 형태의 뜻만 설명하고 1차 미지원 안내. 다른 눈 효과로 대체하지 않음 |
| 모호한 편집 | “코끝을 올려줘” | 위아래 위치와 들림 중 무엇인지 되묻기. 검색 카드만으로 자동 적용하지 않음 |

## 같은 문장셋 검색 비교

[`consult-term-eval-v1.tsv`](consult-term-eval-v1.tsv)의 합성 한국어 30문장에는 동의 표현, 범위 밖 3건, 두 카드가 함께 언급되는 모호 문장 1건을 넣었다. 개인 얼굴·실제 채팅·측정값은 전송하지 않았다. 키워드 기준선은 카드의 별칭 포함 여부로 찾고, 둘 이상 걸리면 답하지 않는다. 비교군은 GMS `text-embedding-3-small`로 카드 문장과 질문을 임베딩한 뒤 코사인 유사도 상위 1건을 찾는다. **실험 전에 정한** 수락 기준은 유사도 ≥0.42와 1·2위 차이 ≥0.06이다. 두 방식 모두 검색 결과만 반환하며 편집을 실행하지 않는다.

| 방식 | 정답 카드 또는 보류 일치 | 범위 밖·모호 문장의 잘못된 카드 선택 | 주요 실패 |
| --- | --- | --- | --- |
| 별칭 키워드 | 23/30 | 0/5 | 인폴드, 눈 세로 폭, 눈 앞머리의 다른 표현 등 7건 보류 |
| GMS 임베딩 | 15/30 | 1/5 | 명확한 비공·매부리·radix도 보류, “콧대와 코끝 차이”를 N01로 잘못 선택 |

임베딩 호출은 합성 텍스트 42개(카드 12·질문 30)의 총 1,541 토큰, 조회 전후 정수 잔액 차이 1크레딧이었다. GMS 잔액은 정수 단위이고 팀의 다른 동시 사용이 있을 수 있어 1크레딧을 이 호출의 확정 과금액으로 보지 않는다. 재현: `python scripts/eval/consult_terms.py`(키워드) 및 서버 밖의 합성 평가 환경에서 `GMS_KEY`를 환경 변수로 넣고 `python scripts/eval/consult_terms.py --embedding`(잔액 하한 검사 후 호출). 스크립트는 키·GMS 응답 전문을 출력하거나 저장하지 않는다.

**판정:** 이 작은 작성자 제작 문장셋에서는 임베딩이 키워드 기준선보다 오류를 줄이지 못했고 모호 문장에서 오검색이 생겼다. 지금은 벡터 저장소·GraphRAG를 제품에 추가하지 않는다. 별칭 검색도 7건을 놓치므로 자동 편집 권한으로 쓰지 않고, 검수 카드가 정확히 하나 걸리는 **용어 설명 후보**에만 쓸 수 있다. 실제 제품 연결 여부는 별도 독립 발화셋과 사람 검수 후 다시 결정한다. 이 결과는 일반 사용자 정확도나 의료 안전성의 증거가 아니다.

## 2026-10-31 코 용어 연결 후보

AI-98에서는 코 카드 N01–N08만 Spring 상담의 **설명 질문**에 연결한다. 편집 동사가 있거나 슬라이더 위치를 묻는 문장은 이 검색을 거치지 않는다. 별칭이 두 카드에 걸리거나 코 질문의 출처 카드가 없으면 뜻을 다시 물으며, 어떤 검색 결과도 편집 action으로 바꾸지 않는다. 답변에는 카드의 설명과 출처 원문 링크를 함께 낸다. 카드의 `clinicalReview: false`는 그대로 유지하고 의료 판단·시술 권고로 쓰지 않는다. 이번 MR의 작성자 검토와 독립 질문 평가 전에는 제품 표현의 최종 검수나 일반 사용자 정확도 완료로 판정하지 않는다.

N01에 ‘코 등쪽’을 동의어로 추가한 뒤 동일한 합성 30문장 재실행은 별칭 24/30, 범위 밖·모호 문장 오선택 0/5다. 이는 기존 작성자 제작 표본의 1건 개선일 뿐 독립 평가가 아니다. 눈 카드 E01–E06은 이번 코 우선 범위에서 제품 검색에 연결하지 않았다.

## 2026-10-31 비공·비주·비순각 답변 분리

S15P31B204-478에서 N06에 함께 담긴 비공·비주·비순각을 N06–N08로 분리했다. 각각의 질문에는 해당 용어의 뜻과 출처를 답하고, 둘 이상 언급하면 한 의미를 추측하지 않고 되묻는다. 이 세 카드의 `candidateCodes`는 비어 있으며 편집 action으로 사용하지 않는다. 기존 30문장에 두 용어가 겹치는 문장 1개를 추가한 작성자 제작 31문장 평가에서 별칭 검색은 25/31, `NONE` 거짓 양성 0건이었다. 여섯 오답은 제품에 아직 연결되지 않은 눈 용어 표현이며 코 용어는 모두 기대 카드 또는 보류와 일치했다. 일반 사용자 정확도나 의료 검수로 해석하지 않는다.

## 2026-10-31 인물·사진 참조 입력

현재 상담은 인물이나 참고 사진과 닮게 코를 만드는 요청을 편집하지 않고 안내한다. 차단된 입력은 공백이 든 이름이나 과거 일부만 마스킹된 기록까지 보호하기 위해 원문 대신 `[인물·사진 참조 요청]`으로 저장하고 GMS에 보내지 않는다. 한 문장에 일반 코 조절과 참조 요청이 섞여도 전체를 적용하지 않는다. 사진 입력을 받아 특징을 분석하는 기능은 [FN-SVC-01](../planning/01_기능명세서_v2.7.md)의 후속 범위이며 이번 차단으로 구현되지 않는다. 텍스트 패턴만으로 모든 고유명사를 식별할 수 없으므로 표현 범위는 회귀 평가에서 계속 확인한다. 기존 서비스 약관의 이름을 `[인물]`로 바꿔 저장한다는 문구는 FE·법무 담당이 실제 저장 표현과 대조해야 한다.
