# 참고 이미지 기반 코 조절 분석 사전 검증

- Jira: S15P31B204-504
- 검증일: 2026-11-02
- 자료: 저장소의 수식 기반 `createSyntheticHead()` 합성 3D 머리 1종. 실제 얼굴·회원 모델·외부 사진은 사용하지 않았다.
- 실행: `cd apps/web && node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/nose-reference-poc.mjs`

동일한 합성 머리의 코 효과 3개에 알려진 값을 준 뒤, 정면·측면 2D 투영을 참고 목표로 만들었다. 파란 점은 기준, 붉은 점은 참고 목표다. 이 그림은 사진이 아닌 3D 정점의 투영이므로 실제 이미지 분석 성능을 의미하지 않는다.

- [정면 전후 투영](nose-reference-front.svg)
- [측면 전후 투영](nose-reference-side.svg)

| 조절 항목 | 합성 목표 원시값 | 관찰 가능한 단서 | 이 PoC의 판정 |
| --- | ---: | --- | --- |
| 콧대 높이 | +0.40 | 측면의 앞쪽 깊이 | 같은 3D 정점 식별자를 알면 역산 가능. 정면 단독 투영의 이동은 0이다. |
| 코끝 앞뒤 | — | 측면 깊이 | 합성 모델에 `nose.tip_projection` 목표가 없어 시험 불가. |
| 코끝 위아래 | −0.30 (`tip_height`만) | 정면·측면 높이 | `tip_height`만 역산 가능. 제품 조절은 `tip_rotation`까지 묶여 있어 완전한 매핑이 아니다. |
| 콧볼 너비 | −0.25 | 정면 좌우 거리 | 같은 3D 정점 식별자를 알면 역산 가능. |

알려진 정점 식별자와 같은 생성 모델을 사용했을 때 3개 목표값은 각각 `+0.40`, `−0.30`, `−0.25`로 수치상 정확히 복원됐다. 이는 **생성에 사용한 모델과 정점 대응을 그대로 역산한 상한 시험**이다. 실제 사진의 정확도, 랜드마크 검출 성능 또는 사용자 체감 품질로 해석하면 안 된다.

## 실패 사례와 비용·권한

- **정면 사진만 있는 경우:** 콧대 효과는 깊이(+Z)만 바꾸므로 정면 2D 위치 변화가 0이다. 코끝 앞뒤 깊이도 정면 사진 하나로는 결정할 수 없다. 시점·크기·조명이 다른 참고 이미지라면 동일한 코 효과와 사진 변화의 대응이 더 모호하다.
- **현재 합성 모델:** 제품의 네 조절에 필요한 5개 원시 효과 중 `nose.tip_projection`과 `nose.tip_rotation`이 없다. 따라서 네 조절값을 모두 복원했다고 말할 수 없다.
- **비용:** 이 시험은 로컬 Node/Three.js 계산만 사용해 외부 AI 호출 0건이다. 실제 이미지 특징 추출 공급자와 모델은 선정되지 않아 서비스 호출 비용은 미측정이다. 한 번의 로컬 명령은 약 5초 걸렸으며 배포 환경의 지연값이 아니다.
- **권한·개인정보:** 합성 수식 메시만 사용했다. 실제 참고 사진을 받으려면 업로드 동의, 보관·삭제 기준, 다른 사람 얼굴 권리, 외부 모델 전송 여부를 정해야 한다. 현 제품의 인물명·사진 닮기 채팅 차단은 유지한다.

## 결정

**자동 적용은 열지 않는다.** 한 시점의 사진에서 네 효과를 식별할 수 없고, 현재 합성 모델도 두 원시 효과가 빠져 있다. 다음 단계는 권한 있는 모델에서 네 조절의 리그·카메라 정렬·랜드마크 대응을 마련하고, 별도 합성 사진 보류셋에서 오차와 실패율을 재는 것이다. 그 전에는 분석 결과도 확정적인 슬라이더 %로 제시하지 않는다.
